# 어드민 비밀번호 초기화

친구가 비밀번호를 잊으면 어드민이 초기화한다. 친구는 어드민에게 받은 임시 비밀번호로 로그인하고, 곧바로 새 비밀번호를 정한다.

제품 맥락: [PRODUCT.md](../../../PRODUCT.md)의 친구끼리 쓰는 앱 전제. 메일 발송 없이 어드민이 직접 돕는다.
용어: [GLOSSARY.md](../../../GLOSSARY.md)의 어드민, 임시 비밀번호를 따른다.
순서와 진행 상태: [plan.md](../trip-day-route-map/plan.md).
앞선 작업: [signup-allowlist](../signup-allowlist/spec.md)(어드민과 어드민 화면).

연결된 결정 계약:
- [backend-platform](../../decisions/backend-platform.md): 인증은 Supabase Auth에 둔다.
- [ui-composition](../../decisions/ui-composition.md): 공식 shadcn component를 쓰고, 상태도 같은 방식으로 표현한다.

승인된 화면: 없다. 어드민 화면과 로그인 화면의 카드 구성을 따르고, 구현 뒤 실제 화면에서 검토한다.

## 사용자에게 보이는 결과

1. 어드민 화면에 **비밀번호 초기화** 칸이 있다. 어드민이 가입한 친구의 이메일을 넣고 초기화를 누르면, 임시 비밀번호가 화면에 한 번 보인다. 어드민은 이것을 카톡 등으로 친구에게 전한다.
2. 초기화하면 그 계정의 이전 비밀번호로는 더 이상 로그인할 수 없다.
3. 친구가 이메일과 임시 비밀번호로 로그인하면, 내 여행 대신 **새 비밀번호 정하기** 화면이 보인다. 새 비밀번호를 정하기 전에는 다른 화면으로 가도 이 화면으로 돌아온다.
4. 새 비밀번호를 두 번 입력해 저장하면 내 여행으로 가고, 이후 평소처럼 쓴다. 다음부터는 새 비밀번호로 로그인한다.
5. 로그인한 사람은 누구나 프로필 화면의 **비밀번호 바꾸기**에서 현재 비밀번호와 새 비밀번호(두 번)를 넣어 비밀번호를 바꿀 수 있다.

## 승인된 범위

- 어드민 화면의 비밀번호 초기화(이메일 입력 → 임시 비밀번호 표시)
- 초기화된 계정은 로그인 직후 새 비밀번호 정하기 화면으로 강제 이동
- 새 비밀번호 정하기 화면
- 프로필 화면의 비밀번호 바꾸기(사용자 요청으로 추가)

## 수용 기준

실제 브라우저와 Supabase Auth로 확인한다.

- AC1. 어드민이 가입한 이메일을 넣고 초기화하면 임시 비밀번호가 보인다. 이메일은 대소문자와 앞뒤 공백을 무시한다. 가입하지 않은 이메일이거나 형식이 아니면 초기화되지 않고 이유가 보인다.
- AC2. 초기화한 뒤에는 이전 비밀번호로 로그인할 수 없고, 임시 비밀번호로는 로그인된다.
- AC3. 임시 비밀번호로 로그인하면 새 비밀번호 정하기 화면이 보인다. 이때 `/`, 여행 화면, 프로필, 어드민 같은 다른 주소를 열어도 이 화면으로 돌아온다.
- AC4. 새 비밀번호가 6자보다 짧거나 두 칸이 다르면 저장되지 않고 이유가 보인다. 임시 비밀번호와 같은 값도 저장되지 않는다.
- AC5. 새 비밀번호를 저장하면 내 여행 화면으로 가고, 이후 어느 화면도 막히지 않는다. 로그아웃한 뒤 새 비밀번호로 로그인할 수 있고, 임시 비밀번호로는 로그인할 수 없다.
- AC6. 어드민이 아니면 초기화를 할 수 없다. 화면이 보이지 않고, 서버 동작을 직접 불러도 거절된다.
- AC7. 초기화하지 않은 계정의 로그인과 화면 이동은 전과 같다.
- AC8. 폰 너비(375px)에서 어드민 화면의 초기화 칸, 새 비밀번호 화면, 프로필의 비밀번호 바꾸기가 가로로 넘치지 않는다.
- AC9. 프로필에서 현재 비밀번호와 새 비밀번호를 넣어 저장하면 바뀐다. 로그아웃한 뒤 새 비밀번호로 로그인되고 이전 비밀번호로는 안 된다. 현재 비밀번호가 틀리거나, 새 비밀번호가 6자보다 짧거나, 두 칸이 다르거나, 현재 비밀번호와 같으면 바뀌지 않고 이유가 보인다.

## 정한 것과 이유

- **본인 확인은 임시 비밀번호로 한다.** 사용자가 정했다. 이메일만으로 재설정 화면을 열면 이메일을 아는 다른 사람이 계정을 가져갈 수 있다.
- **임시 비밀번호는 앱이 만든다(가정).** 헷갈리는 글자(0/O, 1/l/I)를 뺀 영문·숫자 10자로 만든다. 화면에 한 번만 보이고 어디에도 저장하지 않는다.
- **"새 비밀번호를 정해야 함" 표시는 Supabase Auth의 app_metadata에 둔다(가정).** 사용자가 스스로 지울 수 없는 칸이고, 로그인 토큰에 함께 실려서 화면을 옮길 때마다 DB를 따로 조회하지 않아도 된다.
- **어드민의 서버 동작은 Supabase secret key로 한다.** 다른 사람의 비밀번호를 바꾸려면 서버 전용 관리자 권한이 필요하다. 키는 서버 환경 변수에만 두고 브라우저로 보내지 않는다.
- **새 비밀번호 규칙은 Supabase 기본값(6자 이상)을 따른다(가정).**
- **프로필에서 바꿀 때는 현재 비밀번호를 먼저 확인한다(가정).** 로그인된 기기를 다른 사람이 잠깐 쓰더라도 비밀번호를 바꿀 수 없게 한다.

## 범위 밖과 이유

- 비밀번호 재설정 메일(스스로 재설정): 메일 발송 설정이 필요하다. 친구 몇 명이라 어드민이 돕는 것으로 충분하다.
- 다른 기기에 남은 로그인 끊기: 비밀번호를 잊은 사람은 대개 로그인이 끊긴 상태다.

## 미뤄 둔 결정

None.

## 남은 위험

- 임시 비밀번호를 전하는 경로(카톡 등)는 앱 밖이다. 친구가 새 비밀번호를 정하기 전에 임시 비밀번호가 새면, 그 사람이 먼저 로그인해 비밀번호를 정할 수 있다. 어드민이 다시 초기화하면 된다.
- 초기화할 때 다른 기기에 로그인이 남아 있던 세션은, 토큰이 갱신되기 전(최대 1시간)까지 새 비밀번호 화면으로 이동하지 않을 수 있다.

## Setup before implementation

- Supabase secret key를 `.env.local`의 `SUPABASE_SECRET_KEY`에 넣는다(배포 환경이 생기면 그 서버 환경 변수에도 넣는다). 어드민이 다른 사람의 비밀번호를 바꾸는 데 필요하다. 완료 조건: 대시보드 Project Settings → API Keys에 secret key가 있고, `.env.local`에 `SUPABASE_SECRET_KEY` 줄이 있다.
