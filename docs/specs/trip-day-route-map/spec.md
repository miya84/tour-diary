# 여행 만들기와 하루 동선 지도

로그인한 사용자가 새 여행을 만들고 날짜별로 일정 항목을 넣으면, 그날의 하루 동선을 지도에서 한눈에 본다.

제품 맥락: [PRODUCT.md](../../../PRODUCT.md) — 이 작업은 핵심 흐름 중 "여행 만들기 → 일정 입력 → 동선 보기"를 처음으로 한 번 끝까지 돌리는 조각이다.
용어: [GLOSSARY.md](../../../GLOSSARY.md)의 여행, 일정 항목, 장소, 하루 동선을 따른다.

연결된 결정 계약:
- [backend-platform](../../decisions/backend-platform.md) — 데이터 저장과 로그인 방식(Supabase, 이메일+비밀번호).
- [map-provider](../../decisions/map-provider.md) — 지도와 장소 검색 제공자(Google Maps Platform), 길찾기 연결 방식.
- [ui-composition](../../decisions/ui-composition.md) — 화면 구성, 공식 shadcn component 사용, 상태 표현. 지도 표면은 이 계약의 custom UI 예외에 해당한다.

## 사용자에게 보이는 결과

1. 이메일과 비밀번호로 가입하고 로그인한다.
2. 내 여행 목록을 보고, 제목·시작일·종료일을 입력해 새 여행을 만든다.
3. 여행을 열면 여행 기간의 날짜가 차례로 보이고, 날짜를 골라 그날의 일정을 본다.
4. 그날에 일정 항목을 추가한다. 제목은 꼭 입력하고, 장소(구글 장소 검색으로 선택)·시작 시간·메모는 선택이다.
5. 그날의 화면 위쪽 지도에 장소가 있는 일정 항목이 번호 핀으로 찍히고, 번호 순서대로 직선으로 이어진다. 아래쪽에는 그날의 일정 항목 목록이 같은 순서로 보인다.
6. 장소가 있는 일정 항목에서 "지도 열기"를 누르면 구글 지도에서 그 장소가 열려 바로 길찾기를 할 수 있다.
7. 다른 기기에서 같은 계정으로 로그인해도 같은 여행과 일정이 보인다.

## 승인된 범위

- 이메일+비밀번호 가입, 로그인, 로그아웃
- 내 여행 목록과 새 여행 만들기
- 여행 안에서 날짜 선택, 날짜별 일정 항목 추가·수정·삭제
- 구글 장소 검색으로 일정 항목에 장소 붙이기
- 날짜별 하루 동선 지도(번호 핀 + 순서대로 직선 연결)
- 장소가 있는 일정 항목의 "지도 열기" 링크

## 수용 기준

실제 브라우저(폰 너비 포함)에서 확인한다.

- AC1. 새 이메일로 가입하고 로그인하면 내 여행 목록이 보인다. 로그인하지 않은 사용자는 여행 목록과 여행 화면에 들어갈 수 없다.
- AC2. 제목·시작일·종료일을 입력해 여행을 만들면 목록에 나타나고, 열었을 때 시작일부터 종료일까지 모든 날짜가 순서대로 보인다. 종료일이 시작일보다 앞서면 만들 수 없다.
- AC3. 제목만 입력한 일정 항목을 추가할 수 있다. 이 항목은 그날 목록에 보이지만 지도에는 핀이 생기지 않는다.
- AC4. 장소 입력란에 장소 이름(예: "기린코 호수", "Lake Kinrin")을 입력하면 구글 장소 후보가 뜨고, 하나를 고르면 그 장소가 일정 항목에 붙는다.
- AC5. 한 날짜에 장소가 있는 항목이 둘 이상이면, 지도에 핀이 그 날짜 목록 순서대로 1, 2, 3… 번호로 찍히고 같은 순서로 직선이 이어진다. 장소가 없는 항목은 번호와 연결에서 빠진다. 지도는 그날의 핀이 모두 보이게 맞춰진다.
- AC6. 한 날짜에 장소가 있는 항목이 하나뿐이면 핀 하나만 보이고 선은 없다. 하나도 없으면 지도 대신 장소를 추가하라는 빈 상태가 보인다.
- AC7. 일정 항목을 수정하거나 삭제하면 목록과 지도가 새로고침 없이 바로 바뀐다. 장소를 빼면 그 항목의 핀이 사라지고 나머지 핀 번호가 다시 매겨진다.
- AC8. 장소가 있는 일정 항목의 "지도 열기"를 누르면 구글 지도(앱 또는 웹)에서 그 장소가 열린다.
- AC9. 다른 브라우저에서 같은 계정으로 로그인하면 같은 여행과 일정 항목이 보인다.
- AC10. 다른 계정으로 로그인하면 내 여행이 목록에 보이지 않고, 여행 주소를 직접 열어도 내용을 볼 수 없다.

## 확정된 제약과 근거

- 로그인하고 서버에 저장한다. 이번 조각은 여행을 만든 본인만 보고 편집한다. 초대와 공동 편집을 나중에 얹을 때 데이터를 옮기지 않기 위해서다. (사용자 확정, [backend-platform](../../decisions/backend-platform.md))
- 로그인은 이메일+비밀번호다. (사용자 확정)
- 지도와 장소 검색은 구글 지도다. 일본 장소 검색과 길찾기가 정확해야 한다. (사용자 확정, [map-provider](../../decisions/map-provider.md))
- 일정 항목의 장소는 선택이다. 항공편, 이동, 자유 시간처럼 장소가 없는 항목도 같은 목록에 넣을 수 있어야 한다. (사용자 확정)
- 하루 동선은 번호 핀을 순서대로 직선으로 잇는다. 실제 도로 경로와 이동 수단은 이번에 다루지 않는다. (사용자 확정)
- 여행 중 폰으로 빠르게 보는 화면이 중심이다. (PRODUCT.md 경험 원칙)

## 가정 (바꿀 수 있음)

- 여행을 만들 때 입력하는 것은 제목, 시작일, 종료일이다. 여행지 이름이나 멤버는 받지 않는다.
- 하루 안의 순서는 일정 항목을 추가한 순서다. **임시 동작**이며, 아래 미뤄 둔 결정 "일정 순서 변경"이 정해지면 대체된다. 시작 시간을 입력해도 자동으로 정렬하지 않는다.
- 날짜 화면은 위쪽 지도, 아래쪽 목록으로 쌓는다. 기존 여행 수첩의 배치를 따른다.
- 일정 항목을 다른 날짜로 옮기는 것은 수정에서 날짜를 바꾸는 것으로 한다.
- 여행 기간을 줄여서 기존 일정 항목이 기간 밖으로 밀리는 경우는 여행 수정이 범위 밖이라 생기지 않는다.
- 화면 문구는 한국어다.

## 범위 밖과 이유

- 초대, 공동 편집, 실시간 동기화 — 이번 조각은 혼자 쓰는 흐름을 먼저 끝까지 돌린다. 다음 스펙에서 다룬다.
- 일정 순서 변경(끌어서 옮기기 등), 하루 일정 통째로 옮기기 — 아래 미뤄 둔 결정 참고.
- 실제 도로 경로, 이동 시간, 다음 일정까지 남은 시간 — 아래 미뤄 둔 결정 참고.
- 여행 제목·기간 수정, 여행 삭제 — 핵심 흐름에 필요하지 않다.
- 일정 항목 카테고리(항공, 숙소, 식사 등) — 요청되지 않았다.
- 예약함, 경비 기록과 정산, 후보지 투표 — PRODUCT.md에 있지만 별도 작업이다.
- 구글 로그인, 비밀번호 재설정, 계정 삭제 — [backend-platform](../../decisions/backend-platform.md) 참고.
- 기존 여행 수첩 사이트의 데이터 가져오기 — 요청되지 않았다.
- 오프라인 사용 — PRODUCT.md에서 핵심 가치가 아니다.
- 보안 하드닝, 엣지케이스·성능 방어 — AGENTS.md 검증·리뷰 예산.

## 미뤄 둔 결정

- **일정 순서 변경 방식** — 하루 안의 순서를 사용자가 바꾸는 방법(끌어서 옮기기, 위아래 버튼, 시간순 자동 정렬 중 무엇인지). 그때까지는 추가한 순서가 임시 동작이다. 다시 여는 조건: 이 스펙이 기본 브랜치에 들어간 뒤 다음 작업을 고를 때.
- **실제 경로와 남은 시간** — 일정 항목 사이의 실제 이동 경로, 이동 수단, 다음 일정까지 시간이 충분한지 표시. 다시 여는 조건: 이 스펙이 기본 브랜치에 들어간 뒤 다음 작업을 고를 때.
- **초대와 공동 편집** — 초대 방법, 초대받은 사람의 권한, 실시간 반영. 다시 여는 조건: 이 스펙이 기본 브랜치에 들어간 뒤 다음 작업을 고를 때. 로그인 방식 재검토 조건은 [backend-platform](../../decisions/backend-platform.md)에 있다.

## 남은 위험

- 구글 장소 검색과 지도 표시는 Google Cloud 결제 계정에 묶인다. 무료 한도를 넘으면 청구가 생긴다. API 키가 브라우저에 노출되므로 Google Cloud에서 키 사용처를 이 앱 주소로 제한하지 않으면 남이 키를 쓸 수 있다.
- 구글 지도 공식 에이전트 스킬이 원본 YAML 오류로 설치되지 않았다. 구현은 `AGENTS.md`의 스택 공식 맥락에 적힌 공식 문서를 그 시점에 읽고 진행한다.
- 하루 순서가 추가 순서뿐이라, 순서를 바꾸고 싶으면 이번 조각에서는 지우고 다시 넣어야 한다. 기존 수첩의 가장 큰 불편이 순서 변경이었으므로 다음 작업으로 미루는 대가가 크다.

## Setup before implementation

- Supabase Cloud 프로젝트 — 여행과 일정 항목 저장, 로그인에 쓴다. 완료 조건: Supabase 대시보드에 이 앱용 프로젝트가 있고, Authentication 설정에서 Email 제공자가 켜져 있다.
- Google Cloud 프로젝트와 결제 계정 — 구글 지도 사용 조건이다. 완료 조건: Google Cloud 콘솔에서 이 프로젝트에 결제 계정이 연결되어 있다.
- Maps JavaScript API와 Places API (New) 활성화, 브라우저용 API 키 발급 — 지도 표시와 장소 검색에 쓴다. 완료 조건: 앱 밖에서 그 키로 Places API Text Search 요청(예: "Lake Kinrin")을 보내면 장소 결과가 돌아온다.
