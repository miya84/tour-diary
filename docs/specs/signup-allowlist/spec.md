# 어드민 가입 허용 목록

친구들끼리 쓰는 앱이므로, 어드민이 허락한 이메일만 가입할 수 있게 한다. 어드민은 앱 안의 어드민 화면에서 허용 이메일을 추가하고 지운다.

제품 맥락: [PRODUCT.md](../../../PRODUCT.md)의 "초대받은 사람만 함께 편집"을 앱 가입 단계까지 넓힌다. 여행 초대(가입한 회원에게만 보냄)는 그대로다.
용어: [GLOSSARY.md](../../../GLOSSARY.md)의 어드민, 가입 허용 목록을 따른다.
순서와 진행 상태: [plan.md](../trip-day-route-map/plan.md).

연결된 결정 계약:
- [backend-platform](../../decisions/backend-platform.md): 인증과 데이터는 Supabase에 둔다. 가입 제한도 Supabase Auth 안에서 한다.
- [ui-composition](../../decisions/ui-composition.md): 공식 shadcn component를 쓰고, 상태도 같은 방식으로 표현한다.

승인된 화면: 없다. 프로필 화면과 같은 카드·목록 구성을 따르고, 구현 뒤 실제 화면에서 검토한다.

## 사용자에게 보이는 결과

1. 가입 허용 목록에 있는 이메일로만 가입된다. 목록에 없는 이메일로 가입하면 "초대받은 이메일만 가입할 수 있어요. 앱 관리자에게 이메일을 알려 주세요."가 보이고, 계정이 만들어지지 않는다.
2. 이메일은 대소문자와 앞뒤 공백을 무시하고 비교한다. 목록의 `Friend@Example.com`과 가입할 때 쓴 `friend@example.com`은 같은 이메일이다.
3. 어드민의 헤더에는 **어드민** 링크가 보인다. 누르면 어드민 화면(`/admin`)이 열린다. 어드민이 아니면 링크가 보이지 않고, 주소를 직접 열어도 찾을 수 없는 페이지가 나온다.
4. 어드민 화면에서 이메일을 추가하면 목록에 바로 나타나고, 그 이메일은 곧바로 가입할 수 있다. 목록에서 지우면 그 이메일로 새로 가입할 수 없다.
5. 이미 가입한 계정은 목록과 관계없이 그대로 로그인하고 쓴다. 목록에서 지워도 기존 계정은 막지 않는다.

## 승인된 범위

- 가입 직전 서버(Supabase Auth)에서 허용 목록을 확인하고, 없으면 거절
- 어드민 한 명(my.test@yopmail.com 계정), 앱 안 어드민 화면에서 허용 이메일 추가·삭제
- 가입 화면의 거절 안내 문구

## 수용 기준

실제 브라우저와 Supabase Auth로 확인한다.

- AC1. 허용 목록에 없는 이메일로 가입하면 거절 안내가 보이고, Auth 사용자도 프로필도 생기지 않는다. 앱 화면을 거치지 않고 Auth API로 직접 가입해도 똑같이 거절된다.
- AC2. 어드민이 추가한 이메일로는 가입이 되고, 가입 직후 바로 로그인된다(기존 동작과 같음).
- AC3. 목록과 대소문자나 앞뒤 공백만 다른 이메일로 가입해도 허용된다. 어드민이 대문자가 섞인 이메일을 넣으면 소문자로 저장된다.
- AC4. 어드민 화면에서 이메일을 추가하면 목록에 나타나고, 지우면 사라진다. 이미 목록에 있는 이메일을 다시 넣거나 이메일 형식이 아니면 저장되지 않고 이유가 보인다. 지우기 전에 확인을 한 번 더 거친다.
- AC5. 어드민이 아닌 계정에는 헤더의 어드민 링크가 보이지 않는다. `/admin`을 직접 열면 찾을 수 없는 페이지가 나온다. Data API로 허용 목록을 읽거나 바꿀 수도 없다.
- AC6. 로그인하지 않은 사용자도 허용 목록을 읽거나 바꿀 수 없다.
- AC7. 이미 가입한 계정은 목록에 없어도 로그인과 기존 기능을 그대로 쓴다.
- AC8. 폰 너비(375px)에서 어드민 화면이 가로로 넘치지 않고, 긴 이메일도 삭제 버튼과 함께 보인다.

## 정한 것과 이유

- **어드민 화면을 만든다.** 사용자가 정했다. 친구를 추가할 때마다 Supabase 대시보드를 열지 않아도 된다.
- **이메일은 대소문자를 구분하지 않는다.** 사용자가 정했다. 소문자로 바꾸고 앞뒤 공백을 지운 값을 저장하고 비교한다.
- **가입 직전 Supabase Auth 훅(Before User Created)에서 막는다.** 앱 화면에서만 확인하면 공개 키로 Auth API를 직접 불러 우회할 수 있다. 훅은 Auth가 계정을 만들기 전에 돌아서 모든 가입 경로에 적용된다.
- **어드민은 한 명이고, DB에만 기록한다(가정).** 어드민을 추가하거나 바꾸는 화면은 두지 않는다. 바꿔야 하면 SQL로 바꾼다.
- **가입한 뒤에는 목록을 다시 보지 않는다(가정).** 목록에서 지워도 기존 계정은 그대로다. 계정을 막는 일은 이번 범위가 아니다.
- **목록에 가입 여부는 표시하지 않는다(가정).** 표시하려면 Auth 사용자 정보를 읽는 서버 권한이 더 필요하다. 친구 몇 명 규모라 없어도 된다.

## 범위 밖과 이유

- 가입한 계정 막기·삭제, 어드민 여러 명, 어드민 넘기기: 친구 몇 명이 쓰는 앱이라 필요가 생기면 다시 정한다.
- 초대 메일 보내기: 어드민이 친구에게 직접 알려 준다. 메일 발송 설정이 필요해서 범위가 커진다.
- 구글 로그인 등 다른 가입 경로: 지금은 이메일 가입만 있다. 생기더라도 같은 훅이 적용된다.

None.

## 남은 위험

- 훅을 대시보드에서 연결하지 않으면 누구나 가입할 수 있다. 연결 여부는 AC1을 직접 확인해야만 알 수 있다.
- 훅 함수에 오류가 나면 모든 가입이 막힌다. 기존 계정의 로그인은 영향받지 않는다.

## Setup before implementation

- Supabase 대시보드 Authentication → Hooks에서 Before User Created 훅을 Postgres 함수 `public.hook_signup_allowlist`에 연결한다. 이 함수는 이번 작업의 마이그레이션이 만들기 때문에, 마이그레이션을 적용한 직후에 연결한다. 완료 조건: 대시보드의 Hooks 목록에 Before User Created가 켜져 있고, 위 함수를 가리킨다.
