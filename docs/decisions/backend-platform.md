# Backend platform

## Decisions

- 여행 데이터는 Supabase Cloud(Postgres)에 저장하고, 사용자는 Supabase Auth로 로그인한다.
- 로그인 방식은 이메일+비밀번호로 시작한다.

## Boundaries

- 브라우저 로컬 저장만으로 여행 데이터를 보관하지 않는다.
- 다른 로그인 방식(구글 등)을 추가하는 것은 이 계약을 바꾸지 않는다. 기본 방식을 바꾸는 것은 다시 정한다.

## Why

`PRODUCT.md`는 여행을 여러 개 만들고 초대받은 사람만 함께 편집하며 각자 폰으로 보는 앱이다. 처음부터 계정과 서버 저장으로 시작해야 초대와 실시간 동기화를 얹을 때 데이터를 옮기지 않는다. 이메일+비밀번호는 프로젝트의 `setup-supabase` 스킬이 가장 짧게 지원하고, 구글 로그인처럼 OAuth 클라이언트 준비가 따로 필요하지 않다.

## Reconsider when

- 초대 흐름을 정할 때 이메일+비밀번호가 초대받은 사람의 가입을 눈에 띄게 막는다면 로그인 방식을 다시 정한다.

## Still-rejected alternatives

- 로그인 없이 브라우저에만 저장 — 기기를 바꾸거나 저장소가 지워지면 일정이 사라지고, 공동 편집으로 옮길 때 데이터 이전이 필요하다. 혼자 쓰는 앱으로 방향이 바뀌면 다시 본다.
- 구글 로그인으로 시작 — Google Cloud OAuth 동의 화면과 클라이언트 준비가 추가된다. 사용자가 원하거나 초대 흐름에서 필요해지면 추가한다.
